# Release Notes: v1.4.0

## Focus

`v1.4.0` makes the Workbench practical for ongoing remediation work and for
small teams:

- Findings can be closed, rescans resolve and reopen them, and open findings
  carry SLA due dates.
- Each project has a versioned priority policy.
- One instance can be shared behind a login proxy the team already runs.
- The release adds a single-container image and a PyPI project page.

It remains a self-hosted Beta. Team mode delegates sign-in to a trusted reverse
proxy. It adds no built-in accounts, roles, or API tokens, and it does not
certify a public deployment. VPW is still not a scanner, exploitation tool, or
automated patcher.

## Highlights

- **Finding lifecycle.**
  - Analysts close findings as `resolved` or `false_positive` with a required
    reason, one at a time or for up to 500 selected Triage rows.
  - A rescan of the same target and format resolves findings it no longer
    reports and reopens resolved findings it reports again.
  - Every transition is kept in an append-only status history.
- **SLA tracking.** Open findings carry a due date and a state (overdue, due
  soon, on track). Triage shows and filters them and offers an **Overdue**
  view.
- **Project priority policy.**
  - Base-rule thresholds and SLA hours per priority are versioned per project.
    Edit them under Projects > Settings > Configuration.
  - Saving re-evaluates the project, and every decision records the policy it
    used.
- **Fewer blind spots when NVD has no score.**
  - Findings without NVD CVSS use the scanner's CVSS score or reported severity
    instead of ranking as Low.
  - Triage filters findings with missing CVSS or EPSS.
  - Live NVD lookups stay within NVD's rate limits.
- **Team mode.**
  - `AUTH_MODE=proxy` or `[auth] mode = "proxy"` accepts the user that a
    trusted login proxy, such as authentik, Authelia, or oauth2-proxy, names in
    a header.
  - Audit events record who acted.
  - See [Team Mode Behind A Login Proxy](../team-mode.md).
- **Everyday operations.**
  - `vpw backup` and `vpw restore` write and verify portable archives.
  - `vpw import` uploads scanner or SBOM files from CI and waits for the run.
  - `vpw serve` reads optional settings from `vpw.toml`.
- **Container image.**
  - The `serve` target of `backend/Dockerfile` runs `vpw serve` on port 8765
    with a `/data` volume, a health check, and a non-root user.
  - Tagged releases publish it to `ghcr.io/noetheon/vuln-prioritizer-workbench`
    for amd64 and arm64 once container publishing is enabled.
- **Evaluation and scale.**
  - Native evaluation runs without new uploads, versioned replay inputs, and
    immutable decision revisions.
  - Evidence is shared and compressed, finding lists are compact, and exports
    stream, with `json-gzip` for large historical runs.
  - SBOM uploads can optionally be assessed with a local Grype.
- **Browser safety.** State-changing API requests and WebSocket handshakes from
  other sites are rejected.

## Upgrade Notes

- Back up the data directory before upgrading, for example with
  `vpw backup --output vpw-before-1.4.0.zip`.
- `vpw serve` applies the Alembic migrations `0005` through `0018` on start.
  Some of them backfill projections and re-encode stored evidence, so the
  first start on a large database takes longer than usual.
- The evaluation engine is now `scope-evaluator.v2`. Recorded `v1` inputs stay
  replayable. Findings without NVD CVSS may rank higher than before because
  they no longer default to Low.
- Imports resolve findings that a rescan of the same target and format no
  longer reports. For partial exports, use `vpw import --keep-missing-open` or
  the `resolve_missing=false` form field.
- Finding lists return compact decision fields. API clients that need complete
  evidence pass `include_evidence=true` or read the finding detail.
- Current-decision APIs return `503 decision_refresh_pending` until the worker
  has finished its daily refresh. The UI retries these views.
- The container runtime moved to Python 3.14. The package supports Python 3.11
  through 3.14.
- Docker Compose with PostgreSQL remains a deprecated compatibility path for
  existing installations.

The draft GitHub Release for `v1.4.0` must contain:

- `vuln_prioritizer_workbench-1.4.0-py3-none-any.whl`
- `vuln_prioritizer_workbench-1.4.0.tar.gz`
- `vuln-prioritizer-workbench-local-1.4.0.zip`

- `vuln-prioritizer-workbench-local-1.4.0.zip.sha256`
- `dist-sha256.txt`

The workflow publishes to package registries only when the maintainer has
enabled them:

- PyPI `vuln-prioritizer-workbench==1.4.0`, when `PYPI_PUBLISH_ENABLED=true`
- `ghcr.io/noetheon/vuln-prioritizer-workbench:1.4.0` and `:latest`, when
  `CONTAINER_PUBLISH_ENABLED=true`

## Validation

The exact release candidate must pass:

```bash
make package-check-temp
make release-readiness-check
make quality-10-check
```

The tag workflow does the following:

- It reruns `make release-readiness-check`.
- It builds and validates the wheel, sdist, and local ZIP.
- It tests both the built wheel and the source-at-tag install paths.
- It records SHA-256 values and creates the GitHub Release as a draft.

When enabled, each container architecture passes the same image smoke test as
the Docker workflow before its tag is pushed. The draft must remain
unpublished until its tag, notes, asset names, hashes, ZIP manifest, and
workflow evidence have been inspected.

## Known Boundaries

- Team mode trusts the configured proxy completely. Everyone who can sign in
  has full access to every project. The proxy examples in the documentation
  are starting points and are not exercised in CI.
- Package-registry and container-registry availability are separate live
  state. Do not infer them from a GitHub tag or draft Release.
- Public or shared deployment readiness still requires candidate-specific
  proxy, TLS, retention, backup, and operational evidence.
- Live NVD enrichment requests one CVE at a time. First imports with many new
  CVEs take several minutes without an NVD API key.
