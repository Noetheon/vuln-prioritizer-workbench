# VPW-084 GitHub Issue Export Evidence

## Scope

VPW-084 adds the template API GitHub issue export MVP for reviewed Workbench findings:

- `POST /api/v1/projects/{project_id}/github/issues/preview`
- `POST /api/v1/projects/{project_id}/github/issues/export`

The implementation is tracked against the template `/api/v1` contract with template tests,
generated OpenAPI/client coverage, selected `finding_ids`, redacted Markdown issue bodies, and
persisted duplicate keys for explicit GitHub creation.

## Safety Controls

- Preview is always a dry-run and does not require or read an external GitHub token.
- Export defaults to `dry_run: true`.
- Real issue creation requires `dry_run: false`, `repository: "owner/name"`, and a configured
  `token_env` value matching environment-variable-name syntax.
- Token values are read at request time and are never persisted or included in issue markdown.
- Generated issue bodies redact token/API-key assignments, GitHub-token-shaped values, and local
  absolute paths.
- A report-scoped template service token can preview/export; read-only tokens are rejected.
- Created duplicate keys are persisted per project and repository so repeated exports skip already
  created findings.
- The older local Workbench export route also rejects real creation when `token_env` is omitted; the
  VPW-084 public contract remains the template `/api/v1` route above.

## Residual Risk

If GitHub accepts an issue but the network fails before Workbench receives the response, the
reserved duplicate key prevents repeated automatic issue creation, but the operator may need to
reconcile the missing external issue URL manually.
